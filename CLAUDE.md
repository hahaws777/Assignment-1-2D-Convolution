# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A study of seven hand-written FP32 CUDA 2D convolution variants (`naive`, `const`, `tiled`, `im2col`, `im2col_reg`, `implicit`, `gridstride`). It benchmarks them against PyTorch/cuDNN and substitutes them into two layers of pretrained PyNET (RAW-to-sRGB). [HOWTO.md](HOWTO.md) is the authoritative reproduction guide. [evaluation_report.md](evaluation_report.md) is the written report. Its prose and figures are fixed artifacts and are never regenerated by code.

The target environment is Linux + CUDA 12.9 + PyTorch 2.9.1 (cu129) + GCC 13 on an RTX 3060 (sm_86). This checkout is on Windows, so GPU builds and experiments are expected to run under Linux/WSL with `nvcc` on `PATH` and `CUDA_HOME` set. HOWTO §1 has the full environment exports, including `TORCH_CUDA_ARCH_LIST` and `MAX_JOBS`.

## Commands

```bash
python -m unittest discover tests -v                    # full unit suite (no pytest)
python -m unittest tests.test_evaluation_utils -v       # one module (CPU-only, needs numpy/skimage)
python -m unittest tests.test_cuda_convolutions.TestCUDAConvolutions.test_shared_memory_tile_sweeps -v
python test_convolutions.py --output-dir ../some_dir    # standalone sweep: expect 54 passed + 1 rejected const case
```

Test classes use `skipUnless` when torch, CUDA or deps are missing. **Skipped CUDA tests do not validate the GPU build.** If a test is skipped, say so; don't report it as passing.

Experiments all go through `benchmark.py`. Its modes are mutually exclusive: `--operator-size-only`, `--quality-only`, `--repeatability`, `--analyze-repeatability`, `--profile-paths`, and the default full run. HOWTO §4–5 has the exact published invocations. `--analyze-repeatability` and the unit tests in `test_evaluation_utils.py` need no GPU.

**`--output-dir` defaults to `results/`, which holds the published evidence.** Always pass a fresh directory outside the repo (HOWTO uses `../pynet_*_reproduction`). Repeatability runs refuse to mix with existing evidence. Quality runs resume from the same output dir and `.quality_cache/`.

Data and weights: `bash setup.sh` downloads `checkpoints/pynet_level_0.pth`. `python download_zrr_samples.py --count 1204 --full-id 1050 --output data/zrr_test_samples` fetches the test set. Both are excluded from submission.

`run.sh` only works on the original host (it expects sibling `../pynet_env` and `../cuda_env`). Use plain `python` elsewhere.

## Architecture

There is no package or build step. The CUDA extension is JIT-compiled on first use by `runtime.extension()` via `torch.utils.cpp_extension.load` (name `pynet_seven_convolutions`, `-O3`). It is cached per process. Compilation time is excluded from all timings.

Layering, bottom to top:

- [convolution/cuda/conv2d_kernels.cuh](convolution/cuda/conv2d_kernels.cuh): every `__global__` kernel plus the `ConvDims` struct, the `c_weight` constant buffer (`CONV_MAX_CONST_W` = 16384 floats), and helpers like `tiled_smem_bytes`. `im2col`/`im2col_reg` share `im2col_kernel` and differ only in the GEMM (`gemm_tiled<16>` vs `gemm_reg<…>`, with two template configs selected by `K >= 32`).
- [src/convolution.cu](src/convolution.cu): the single pybind entry point `convolution(x, w, b, method, stride, padding, tile, grid_blocks)`. It validates input (contiguous FP32 CUDA, same device), computes P/Q, allocates output, picks launch geometry and dispatches on the `method` string. Method-specific constraints live here: `const` requires the default stream and ≤16384 weights; `tiled` requires tile ∈ {8,16,32} and a smem fit check; `gridstride` uses `grid_blocks` or 8×SM count.
- [src/runtime.py](src/runtime.py): `METHODS`, `TARGETS`, `load_model()` (strict, `weights_only=True`, strips `module.` prefix), and `CustomConv`/`replace_convolutions()`. These swap exactly two PyNET layers, `conv_l1_d1.conv_3a.conv2d` (4→32) and `conv_l0_d1.conv2d` (16→3). `CustomConv` requires the original `nn.Conv2d` to have padding 0, because PyNET does reflection padding outside the conv. It always calls the kernel with padding 0.
- [evaluation.py](evaluation.py): Bayer packing (`pack`, alias `pack_bayer_mosaic`, giving RGGB → `[B, Gr, R, Gb]` scaled by 1/1020), quality metrics (PSNR/SSIM/MS-SSIM/MAE/RMSE/CIEDE2000), the cuDNN-agreement tolerance (`agreement`: atol 2e-5, rtol 1e-4), and the repeatability statistics (paired process medians, bootstrap CI, sign-flip test, Holm).
- [benchmark.py](benchmark.py): the experiment orchestrator and CLI. It inserts `src/` into `sys.path`; tests and `test_convolutions.py` do the same.

**Adding or renaming a convolution method touches three places that must stay in sync:** the kernel in the `.cuh`, both the method allow-list `TORCH_CHECK` and the dispatch branch in `convolution.cu`, and `METHODS` in `runtime.py`.

## Extension experiments (`extensions/`)

Follow-up kernels `tiled_mk` (several output channels per thread) and `implicit_reg` (register-tiled implicit GEMM with an auto fallback) are built as **separate** extensions (`pynet_ext_tiled_mk`, `pynet_ext_implicit_reg`) via `extensions/common.py:load_extensions()`. `tiled_mk` is not in `METHODS`. `conv2d_implicit_reg` itself was moved into `conv2d_kernels.cuh`, and the published `implicit` method now runs its auto mode (`implicit_use_reg`: register tiles unless they launch fewer blocks than SMs). So `implicit` timings no longer match the report, which measured the original `conv2d_implicit_gemm`. The extension scripts get that original kernel via `ir.implicit_reg(..., mode=2)`. Their scripts write to `results/extensions/`, never to the top-level `results/`. [results/extensions/FINDINGS.md](results/extensions/FINDINGS.md) summarizes what the evidence supports.

These experiments add a second timing metric. **CUDA-graph replay** (`common.graph_time`) gives GPU-only time. The original **CUDA-event** metric includes host dispatch, which dominates small cuDNN calls. Keep the two metrics separate when making speed claims against cuDNN.

## Constraints worth knowing

- [src/pynet.py](src/pynet.py) and [src/msssim.py](src/msssim.py) are unmodified upstream PyNET-PyTorch files (CC BY-NC-SA 4.0). Do not edit them.
- Timing methodology is deliberate: FP32, TF32 disabled, cuDNN autotune on for performance, deterministic cuDNN for quality, CUDA events around full invocations (allocation and `const` weight upload included). Changes to timing code alter what the report's numbers mean.
- The FP32 bias-addition order differs between kernels. That is why `naive`, `const` and `gridstride` exceed tolerance on test image 747, which is a documented, expected result rather than a bug to "fix". Changing accumulation order in kernels changes published correctness results.
- HOWTO links `evaluation_report_zh.md`, but that file is not present in this checkout.
